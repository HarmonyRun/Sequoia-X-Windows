# 自定义选股策略：规则 DSL 设计

本文档定义「自然语言 → 结构化规则」的目标格式。大模型只负责把中文描述翻译成这份
JSON，真正的计算由解释器完成——**不让大模型生成可执行代码**。

## 为什么不让大模型直接写 Python

1. **安全**：生成的代码能读写文件、发网络请求、改数据库
2. **可靠**：引用不存在的模块、写错列名、忘记长度边界，都会让整条流水线挂掉
3. **可审核**：用户看不懂代码，但能看懂「MA5 上穿 MA20 且 成交量 > 20日均量×1.5」
4. **可编辑**：生成的规则用户能直接改数字，不必重新问大模型

## 顶层结构

```json
{
  "name": "缩量回调后放量收阳",
  "description": "连续三天缩量回调，今天放量收阳线",
  "universe": { "boards": [...], "market_cap": {...} },
  "rank": { "by": "...", "top": 20 },
  "conditions": { ... },
  "sort": { "key": "...", "desc": true },
  "limit": 50
}
```

所有字段除 `name` 和 `conditions` 外都可省略。

---

## 1. 字段说明

### name
策略名，中文，2~20 字。显示在工作台和飞书卡片标题上。

### description
一句话说明这个策略在找什么。可选，用于界面展示。

### universe —— 在哪些股票里选

不写 = 全市场（等价于 `get_local_symbols()`）。

```json
{
  "boards": ["沪市主板", "创业板"],
  "exclude_st": true,
  "market_cap": { "min_yi": 50, "max_yi": 500 },
  "symbols": ["600519", "000001"]
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `boards` | string[] | 板块白名单。可选值：`沪市主板` `深市主板` `创业板` `科创板` `深市中小板` |
| `exclude_st` | bool | 排除 ST 股（名称含 ST）。默认 true |
| `market_cap.min_yi` / `max_yi` | number | 流通市值区间，单位亿元。**⚠️ 当前预留：本地没有市值数据，配了也不会生效**（见第 6 节） |
| `symbols` | string[] | 直接指定股票池，指定了就忽略上面全部 |

### 板块的判定依据

按代码前缀推断，实测分布（2026-10 全库 5225 只）：

| 板块 | 前缀 | 只数 |
|---|---|---|
| 沪市主板 | `600` `601` `603` `605` | 1,702 |
| 创业板 | `300` `301` `302` | 1,410 |
| 深市中小板 | `001` `002` `003` | 1,083 |
| 科创板 | `688` `689` | 618 |
| 深市主板 | `000` | 412 |
| 北交所 | `920` `8` `4` | 少数 |

### conditions —— 选股条件（核心）

条件是一棵**树**，每个节点是以下两种之一：

**逻辑节点**（组合子）：
```json
{ "all": [ 条件1, 条件2 ] }      // 全部满足（AND）
{ "any": [ 条件1, 条件2 ] }      // 任一满足（OR）
{ "not": 条件 }                   // 取反
```

**叶子节点**（可计算的判断）：见下面第 2 节。

### rank —— 截面排名（可选）

先按条件筛，再取排名前 N。**这是"全市场最强"类说法的实现方式**。

```json
{ "by": "pct_chg_20d", "top": 20, "desc": true }
```

| 字段 | 说明 |
|---|---|
| `by` | 排序依据，见第 3 节指标列表 |
| `top` | 取前多少只 |
| `desc` | true=从大到小（默认） |

### sort —— 结果排序（可选）

```json
{ "key": "amount", "desc": true }
```
不写则按代码排序。只影响推送顺序，不影响选股集合。

### limit —— 最多返回多少只

默认 100，防止一个宽松规则选出几千只把飞书卡片撑爆。

---

## 2. 叶子条件

统一格式，`left` 是左边（指标或数字），`op` 是比较符，`right` 是右边。

```json
{ "left": {"ind": "close"}, "op": ">", "right": {"ind": "ma", "period": 20} }
```

### op 可选值

| op | 含义 | 备注 |
|---|---|---|
| `>` `<` `>=` `<=` | 数值比较 | |
| `cross_above` | 左**上穿**右 | 昨天左≤右 且 今天左>右 |
| `cross_below` | 左**下穿**右 | 昨天左≥右 且 今天左<右 |
| `between` | 左在 [right[0], right[1]] 之间 | right 为两元素数组 |
| `rising` / `falling` | 左连续 N 天递增/递减 | 用 `period` 指定天数，默认 2 |
| `above_for` / `below_for` | 左连续 N 天大于/小于右 | 用 `period` 指定天数 |

### 操作数（ind）

**价格与成交量**
| ind | 说明 |
|---|---|
| `open` `high` `low` `close` | 当日开高低收 |
| `volume` | 当日成交量 |
| `amount` | 当日成交额 |
| `pct_chg` | 当日涨跌幅（%） |

**均线类**（都支持 `period`）
| ind | 说明 |
|---|---|
| `ma` | 收盘价 N 日均线 |
| `ema` | 收盘价 N 日指数均线 |
| `vol_ma` | 成交量 N 日均值 |

**技术指标**
| ind | 参数 | 说明 |
|---|---|---|
| `macd_dif` | `fast`(12) `slow`(26) | MACD 快线 |
| `macd_dea` | `fast` `slow` `signal`(9) | MACD 慢线 |
| `rsi` | `period`(14) | 相对强弱 |
| `boll_upper` / `boll_lower` / `boll_mid` | `period`(20) `std`(2) | 布林带 |
| `boll_width` | 同上 | (上轨-下轨)/中轨 |
| `atr` | `period`(14) | 真实波幅 |
| `highest` / `lowest` | `period` | N 日内最高/最低价 |
| `hhv_close` / `llv_close` | `period` | N 日内收盘最高/最低 |

**形态与统计**
| ind | 参数 | 说明 |
|---|---|---|
| `consecutive_up` / `consecutive_down` | — | 连涨/连跌天数 |
| `vol_ratio` | `period`(20) | 当日量 / N 日均量 |
| `pct_chg_nd` | `period` | 最近 N 日累计涨跌幅（%） |
| `drawdown_from_high` | `period` | 距 N 日最高价的回撤（%，负值） |
| `gap_up` | — | 向上跳空幅度（%），未跳空为 0 |
| `is_yang` / `is_yin` | — | 1=阳线 / 1=阴线 |
| `close_position` | — | 收盘在当日振幅中的位置，0~1 |

**截面排名**
| ind | 参数 | 说明 |
|---|---|---|
| `rank_pct` | `by`(指标名) `period`? | 该股在某指标上的全市场百分位排名，0~100。**属截面指标，计算成本较高** |

**常量**
```json
{ "const": 1.5 }
```

### 简写

常用写法允许省略 `{"ind": ...}` 外壳，直接写指标名：

```json
{ "left": "close", "op": ">", "right": { "ind": "ma", "period": 20 } }
```

## 3. 完整示例

**例 1：缩量回调后放量收阳**
```json
{
  "name": "缩量回调放量收阳",
  "description": "连续三天缩量回调，今天放量收阳线",
  "conditions": {
    "all": [
      { "left": "close", "op": ">", "right": "open" },
      { "left": "vol_ratio", "op": ">", "right": { "const": 1.5 } },
      { "left": "pct_chg", "op": "between", "right": [{ "const": 0 }, { "const": 6 }] },
      { "left": "close", "op": ">", "right": { "ind": "ma", "period": 60 } }
    ]
  }
}
```

**例 2：均线多头排列且突破 20 日新高，只要市值 50~300 亿的**
```json
{
  "name": "多头排列突破新高",
  "universe": {
    "exclude_st": true,
    "market_cap": { "min_yi": 50, "max_yi": 300 }
  },
  "conditions": {
    "all": [
      { "left": {"ind":"ma","period":5}, "op": ">", "right": {"ind":"ma","period":10} },
      { "left": {"ind":"ma","period":10}, "op": ">", "right": {"ind":"ma","period":20} },
      { "left": {"ind":"ma","period":20}, "op": ">", "right": {"ind":"ma","period":60} },
      { "left": "close", "op": ">=", "right": { "ind": "highest", "period": 20 } }
    ]
  }
}
```

**例 3：全市场 20 日动量最强的 30 只（截面排名）**
```json
{
  "name": "20日动量最强",
  "conditions": { "left": "close", "op": ">", "right": { "ind": "ma", "period": 20 } },
  "rank": { "by": "pct_chg_20d", "top": 30, "desc": true },
  "limit": 30
}
```

**例 4：创业板里 RSI 超卖后回升**
```json
{
  "name": "创业板RSI超卖反弹",
  "universe": { "boards": ["创业板"] },
  "conditions": {
    "all": [
      { "left": {"ind":"rsi","period":14}, "op": ">", "right": { "const": 30 } },
      { "left": {"ind":"rsi","period":14}, "op": "rising", "period": 2 }
    ]
  }
}
```

## 4. 数据依赖与失败处理

| 条件 | 依赖 | 取不到时 |
|---|---|---|
| 全部 `ind` | `symbol` 的日线（本地库已有） | 该股跳过 |
| `market_cap` | 股票名称表附带的市值 | **⚠️ 当前预留，见第 6 节** |
| `boards` | 代码前缀推断 | 前缀无法识别时归入 `其它` |
| `rank_pct` | 全市场截面数据 | 需先加载全市场，性能敏感 |

**核心原则**：任何单个条件失败都不能影响其它条件，更不能让整个策略崩掉——
与现有 7 个策略「单股异常 continue」的处理方式保持一致。

---

## 5. 校验规则（保存前必须过）

1. `name` 非空、≤20 字
2. `conditions` 非空
3. 所有 `ind` 必须在白名单内
4. 所有 `op` 必须在白名单内
5. `period` 必须 ≥1 且 ≤250
6. `rank.top` 1~500，`limit` 1~500
7. 树深度 ≤5（防止大模型生成病态结构）
8. 总叶子节点数 ≤20（防止性能失控）

任一不满足 → 拒绝保存并返回具体原因，前端展示给用户。

## 6. 已知限制：市值条件（预留）

`market_cap` 字段**已定义但当前不生效**。原因和后续做法：

**为什么现在没有**：本地 `data/name_cache.json` 只有 `{代码: 名称}` 的字符串映射，
**不含市值字段**；日线表里也没有。所以拿不到流通市值。

**当前行为**：如果用户配了 `market_cap`，解释器**跳过该条件、继续算其余条件**，
并在返回结果里带一条 `warnings`（界面和日志都会显示），
例如「市值条件已忽略：本地没有市值数据」。

**为什么要留这个字段**：schema 一旦发布，改起来两边（解释器 + 大模型提示词）都要动。
先把位置占住，等市值数据接进来就能直接生效，不需要改 schema、不需要让用户重建策略。

**将来怎么补**：用 akshare 的 `stock_zh_a_spot_em`（一次请求返回全市场总市值/流通市值），
结果缓存到 `data/market_cap.json`，每天随日常回填刷新一次。
届时只需在解释器里把「跳过」改成「读取缓存」，**DSL 格式和已保存的策略都不用动**。

**⚠️ ST 过滤的注意点**：`exclude_st` 依赖名称表里的 ST 标记。名称表由 akshare 提供，
覆盖度可能出现波动（实测统计口径需复核）。若名称表缺失，`exclude_st` 同样降级为
「跳过该条件 + 记警告」，不会让整个策略失败。
